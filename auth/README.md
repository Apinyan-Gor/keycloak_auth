# auth — Nuxt 3 app with users API

This folder contains a Nuxt 3 application with server API routes (SQLite by default), Swagger docs (via @scalar/nuxt) and basic pages to manage users.

Quick start

1. Install dependencies:

```bash
cd auth
npm install
```

2. Create `.env` (example already provided). Default uses sqlite: `DATABASE_URL=sqlite:./database.db`.

3. Seed sample data:

```bash
npm run seed
```

4. Run dev server:

```bash
npm run dev
```

Open http://localhost:3000/users to see the users page. Open http://localhost:3000/docs for Swagger UI (generated by @scalar/nuxt).

Files added by the scaffold:

- `server/utils/initDb.ts` — ensure Prisma client & schema are initialized on start
- `server/api/v1/users.*` — GET/POST/PUT/DELETE endpoints with JSDoc and zod validation
- `composables/useUsers.ts` — composable used by pages
- `pages/users`, `pages/users/[id].vue`, `pages/add-user.vue` — SSR pages
- `assets/css/tailwind.css`, `tailwind.config.cjs` — Tailwind setup
- `scripts/seed.mjs` — seed DB with sample users

Additional notes:

- To set an API token for client requests (used by `nuxt-api-party`), open `/login` and paste a bearer token. The token will be stored in localStorage and used for subsequent requests to `/api/v1/*`.
- Swagger UI is available at `/docs` and reflects JSDoc comments in `server/api/v1` files.

Notes

- The API routes use JSDoc comments for basic OpenAPI generation by `@scalar/nuxt`.
- Use `DATABASE_URL` to switch to Postgres or MySQL. The project uses Prisma as the single ORM; set `DATABASE_URL` to your database (for example `postgresql://...` or `mysql://...`) and run the provided `npm run prisma:push` script to generate the client and push the schema.
